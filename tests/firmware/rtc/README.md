# RTC protocol tests

Run `sh tests/firmware/rtc/run.sh` with ArduinoJson **7.4.3** installed. Set `ARDUINOJSON_INCLUDE` to its `src` directory outside the normal Arduino library location. `RTC_SANITIZE=1` adds AddressSanitizer and UndefinedBehaviorSanitizer; `CXX` selects a compiler. The script neither opens a serial port nor starts a network client.

Tests execute the actual `RtcSctp.h` and `RtcRpc.h` implementations. They cover checksum and verification tags, state cookies, ordered delivery and duplicate suppression, receive gaps and cumulative acknowledgements, transmit acknowledgements and bounded retries, TSN wraparound, heartbeat/shutdown, maximum request assembly, multi-frame replies, canonical base64, monotonic request numbers, malformed packet boundaries, three-DATA packets exceeding 1200 bytes, bounded DATA fragment reassembly with duplicate/reordered fragments and invalid start/end/SSN/overflow cases, stale callback clocks and timer rollover, and the last-response/next-request race in both SCTP chunk orders. An additional case delivers the next request before the old tail's SACK, loses that SACK, and verifies exact old-frame retransmission while the next response waits.

These are host protocol tests, not radio or browser acceptance. The transport intentionally supports only one reliable ordered, externally negotiated stream (channel 0), complete text messages no larger than 512 bytes, an eight-slot receive window and one outstanding send. It reassembles ordered SCTP DATA fragments within the same 512-byte message limit, retaining one 512-byte assembly buffer. Receive packets may contain up to 2048 bytes; outbound packets remain limited to 1200 bytes. It does not advertise partial reliability, additional streams or message interleaving. The full production build and on-board Wi-Fi/BLE memory checks belong to the main firmware acceptance.

RPC frames have seven fields: `v`, `type`, `id`, `n`, `seq`, `end`, `data`. `n` starts at 1 for each connection and is consumed before application dispatch; `seq` starts at 0 for each RPC. All non-final decoded chunks are exactly 256 bytes. Requests are at most 12,288 bytes, responses 16,384 bytes. The last response frame is owned by SCTP as soon as `sendText` succeeds, so the RPC can release its assembly buffer before that frame's SACK; the next response remains blocked by SCTP's outstanding packet.
