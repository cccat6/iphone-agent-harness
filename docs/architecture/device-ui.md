# Device connection UI

The device panel separates imported bridge information, live bridge connection, usable Bluetooth target and screen sharing. First obtain information from the desktop USB link or device manager, return to Harness and connect. The manager does not remain open during control.

A connected selected phone is ready after current firmware binds it. The eight-digit input test is optional: its readonly collector accepts trusted foreground digit events and rejects pasted or synthetic input. Older firmware may need its legacy test or update. Full Keyboard Access is neither required nor prohibited; enable AssistiveTouch using the phone tutorial.

New-session creation requires a live usable target. Existing conversations remain readable offline; absent hardware is reported clearly and cannot receive input. Closing or losing RTC clears live readiness. Screen sharing is explicitly authorized by the user and is not inferred from connection status.

The installer only opens serial after user selection. Setup information remains local; connection links contain public connection metadata rather than AI credentials. Updated metadata is saved before connection. Latest multi-client enrollment/import changes are prepared in source but not physically validated on a flashed board.
