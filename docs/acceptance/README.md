# Complete acceptance checklist

[简体中文](zh-Hans.md) · [Release evidence summary](../research/release-acceptance.md)

This checklist covers the delivered Web application, ESP32 bridge, content and release. Desktop verification belongs to the project maintainers; the user is only asked to join the deferred physical-phone acceptance below. A checked automated or mock row is **not** a physical-phone pass.

Evidence snapshot: 2026-10-18. `A` = passed automated/host test in the recorded suite; `N` = passed native desktop-browser interaction; `L` = passed real service/device request from Mac; `D` = inspected source/document/content. `P` = deferred phone acceptance; `F` = a release gate awaiting its recorded receipt (none remain in the desktop inventory). Linked test files describe coverage; linked reports record execution. Prior reports are dated candidate snapshots, not proof that later edits were deployed. No credentials, owner codes, Wi-Fi values, challenge digits or user screens belong in this checklist.

## Deferred phone acceptance — only phone cooperation is required

Do this **after** maintainers close R01–R07 and supply the final C3 image/site. Use a harmless test app/document and short reversible tasks. Record device/OS/Safari, board boot/image version and network type; record only pass/fail, public IDs and frame references. Keep credentials and challenge digits out of reports. Each unchecked box is pending, not a known failure. The project team prepares the board, site, model and optional MCP fixtures and collects desktop diagnostics; the user need not build, inspect logs, run scripts or repair servers.

- [ ] **P01 — Entry and language.** On iOS/iPadOS 27+ Safari open the final HTTPS site; reach session list and chat, Settings, device panel and Skills. Choose your language, reload, check safe area/keyboard/scroll and return/back navigation. Confirm the selected language and user text remain correct.
- [ ] **P02 — First setup.** With the prepared board, join its protected setup AP if needed, submit local Wi-Fi/origin/current time, finish and return to normal Wi-Fi. Install the supplied board CA profile and explicitly enable full trust. Compare the independently supplied fingerprint; reach the unique HTTPS DNS name without bypassing a warning. Maintainers handle USB flashing/configuration.
- [ ] **P03 — Trusted connection and restart.** Enter the board origin/fingerprint, pair with the owner password and confirm actual status; an address alone must not show control. Reload/reconnect and board reboot must preserve only appropriate saved configuration, clear stale run proof, and provide a recoverable re-verification flow.
- [ ] **P04 — Correct phone proof.** Pair Bluetooth **iPhone Agent**, enable AssistiveTouch, disable Full Keyboard Access; focus the dedicated verification field before starting the challenge. Eight real HID digits must arrive in that field and confirmation must select this phone. No paste/manual substitute. Restored token or HTTP pairing alone must leave control disabled until fresh proof.
- [ ] **P05 — Sharing and observation.** Explicitly start screen sharing, move to a harmless second app and obtain a new frame through the Harness. Confirm actual screen/target/orientation, frame freshness and original/scaled dimensions. A visible share state alone is insufficient. Denial or stopping share must be clear and recoverable.
- [ ] **P06 — Real model and local data.** Use the prepared API profile: fetch models, send Chat, switch account/model and confirm actual answers. Check a screenshot observation with a vision-capable model. Create two sessions/drafts; rename/pin/search/archive/restore; reload a sent message; export and reimport a disposable session; verify image/history retention. Optional disposable deletion needs explicit confirmation. Test memory-only reload and optional encrypted unlock with your own passphrase without sharing it.
- [ ] **P07 — Modes and task loop.** Chat performs no phone action; Plan can describe/observe without modifying; Task obtains this run's lease. Ask a short multi-step test with a visible final state and a missing-information question. Confirm budgets, progress/blocked/completed state and final evidence describe the screen actually observed.
- [ ] **P08 — Basic input and text.** In a safe app verify tap position, Consumer Home, supported key/modifier/release and short supported text entry. Observe each result on the phone. Verify unsupported Unicode/keys are explained rather than claimed successful. No native multitouch or Apple Fn promise.
- [ ] **P09 — Gesture timing and temporal evidence.** Compare a drag with endpoint hold against a same-path swipe released in motion; inspect actual post-release list displacement/inertia. Try a short drag/drop and complete down/move/up sequence. Request motion observation; actual frame count/timestamps must be honest, including insufficient evidence. Do not infer timing success from `hid_submitted`.
- [ ] **P10 — Batch and coordinates.** Run tap→released capture→swipe→capture, and a review checkpoint that returns to the model before a decision. Confirm screenshots precede dependent steps. Rotate once between plans; stale coordinates must be rejected/reobserved. Verify full-display mapping near safe areas and after returning from another app.
- [ ] **P11 — Stop and recovery.** Cancel during streaming and during a harmless short gesture; stop screen sharing; briefly background Safari; disconnect/reconnect Bluetooth or Wi-Fi with team guidance. Observe no stuck key/pointer, no further dependent input, truthful unknown/release state, and an explicit fresh-proof/replan recovery. Reboot invalidates old boot/lease work. Team measures delays; a short pass does not promise unlimited background execution.
- [ ] **P12 — Skills, identity and backup.** Open all ten built-ins, enable/disable one and reload; load relevant guidance during P07–P10. Create/edit/export a harmless own Skill and encrypted identity backup, restore it deliberately and confirm creator ID. Downloaded/builtin Skills stay read-only. Context and image settings persist; after a long disposable conversation, compaction must retain task/recent evidence without presenting a summary as new observation.
- [ ] **P13 — Community.** Browse/download a prepared signed package and use it locally. If public publishing is desired, explicitly publish a harmless own package, verify its returned revision/read-only download, then let the team remove only disposable acceptance data. Nothing should upload a conversation or key. Publishing is optional for local operation.
- [ ] **P14 — Optional MCP.** Use a team-prepared browser-CORS-compatible HTTPS server: connect, select one read-only tool and enable; Task calls it once; Chat/Plan do not call it. Revoke and confirm rejection. Simulated interrupted mutation is reconciled by the team. Do not use the Node-only Cloudflare report as a Safari pass.
- [ ] **P15 — Optional Codex subscription.** Only if you elect to authorize: use the explicit official login, cancel once, then sign in; read your real directory, perform one short Responses call and verify refresh/reload unlock. Record actual CORS/authorization errors. No one needs to disclose tokens or local Codex files. Registered loopback SIWC is a separate runtime path.
- [ ] **P16 — Optional second phone / iPad.** Pair/prove each target separately and run harmless distinct tasks. Switch targets, contend for a writer, disconnect/reconnect one target and test reconnect/handle reuse with team instrumentation. Confirm zero input reaches the other phone, separate leases/results and workable sequential TLS service. Repeat iPad desktop-UA entry/orientation if available. One-phone acceptance does not establish two-target isolation or throughput.
