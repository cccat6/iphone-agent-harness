# 默认免连接码的 ESP32 桥

按用户要求，日常连接不再是固定顺序的配网向导。默认地址为 `http://igent.local`，固件默认关闭连接码，网页预填地址并折叠可选配置。已经加入局域网的设备无需再次配网。

网页连接、手机蓝牙和输入测试分别显示状态。系统蓝牙已连接不等于浏览器已建立局域网通信；网页连接桥后才读取手机列表。保存的浏览器信息自动复用；旧自动生成的 `harness-<12 hex>.local` 地址迁移到默认名称，自定义地址不改。仅在核验同一设备身份后读取状态返回 401 时，旧浏览器凭据重新登记一次。

## 设备管理

设备的 `/settings`（或 `/`）提供本地管理页，可以修改本地域名、开启或关闭连接码。默认无需输入码即可登记浏览器；开启后，新登记需要正确连接码。已登记浏览器使用自己的 token；手机输入测试与控制租约仍保留。

配置与 Wi-Fi、蓝牙绑定分别保存。改名成功后返回新地址，并在设备空闲时重启。配网返回链接和 USB 设置链接在默认关闭模式不携带 owner 码；开启模式才包含所需连接码。

## 实物验证

最终候选仅写入授权的 C3 串口 `1101`，四段写入校验通过，保留 Wi-Fi 和蓝牙绑定。四平台固件同源，发布 C3 与实际刷写文件一致：18 文件源 SHA `8b8453917df57e1103c910f23847065cd0387ee90a1b9beee893f1371d0b38ee`，C3 application SHA `f3680b68dcc48f2692fda122e73ab71d3d1b8b1b462bec198b40e0f21be99a57`。

- 系统解析 `igent.local` 后，实际 HTTP 身份接口返回固定名称与 `pairingCodeRequired:false`。
- 生产 DeviceClient 使用空连接码登记成功，仍不会伪造手机输入证明。
- 实际开启连接码后，空码、错误码分别被拒绝，正确码可连接；随后恢复默认关闭。
- 实际修改为临时名称，观察重启后新名称生效；再改回 `igent`，观察再次重启后恢复 `igent.local`，连接码保持关闭。
- 测试没有发送手机输入。最终重启后的手机蓝牙状态与网页 API 测试分别记录，不能把管理测试算成手机操作通过。

## 修复与验收

独立 R1 发现并修复过期凭据恢复；R2 发现配网返回链接仍带隐藏连接码；实物测试发现空 Core 槽位的 releasePending 被误算为忙碌，导致设置无法保存。两处固件问题修复、重新编译和刷写后，实际管理检查通过。

全新 [R3](optional-bridge-independent-r3.md) 没有发现新可复现问题。完整网页测试 525 项、契约 29 项以及固件主机/实际渲染测试通过。4 平台固件与发布封印已验证。

网页日常面板在本地生产 UI 中检查过；真实管理 API 和真实管理 HTML 均已读取。内嵌浏览器未能解析 `.local`，浏览器工具的后续导航也超时，因此不把本轮管理页记作原生浏览器完整交互通过；系统解析及 HTTP 读写结果保留独立证据。没有改变用户浏览器的代理或 DNS 设置。
